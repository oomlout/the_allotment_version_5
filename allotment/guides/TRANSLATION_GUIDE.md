# Platform translation workflow

The runtime editorial source is [PLATFORM_TRANSLATION_PROMPT.md](PLATFORM_TRANSLATION_PROMPT.md). Update that file for editorial changes. Every prompt includes its complete platform guidance, rationale, calibration examples and schema 2.0 output contract, followed by the actual post, image notes, links, confirmed context and unique capture tags. No previous chat, bundle, example file or separate schema is needed. Historical examples are calibration, never input for a new post. [platform_translation.md](../../platform_translation.md) preserves the original downloaded document, source links and checksum for provenance; it is not sent to ChatGPT.

## Use

1. Save a post, then open **Translate** on its page. It can still be a local draft.
2. Choose destinations and add confirmed context if needed. **Generate versions** sends the saved text, original images, link metadata and context to the signed-in ChatGPT account in normal Chrome.
3. Choose the Chrome window during the five-second handoff. The worker opens a fresh tab, snaps top-left and offers the usual eight-second countdown with Pause/Resume and Stop. Keep the desktop idle after the countdown; F8 stops.
4. The worker automatically loads its captured JSON into **Platform text** on the post page. Review or edit each message, with separate native titles and tags. Answer questions in Confirmed context and generate again when needed.
5. **Save platform text** selects the checked versions for Sow and persists them across restarts. Unchecked destinations use the original source. **Use versions for Sow** can still select an immutable captured result directly. Changing the source makes selected text stale; review and save it again, or choose **Use original for all platforms**. Manual editing may change Twitter's wording without changing the original source tweet.
6. Publish locally and use Sow normally. Platform test approvals still apply; held editorial versions cannot be prepared. Final social submission is manual.

The JSON download and on-page messages come from the same validated object. Medium's recipe receives its separate title plus body. Other recipes receive only the message. Native Flickr titles, native tags and image descriptions remain available for manual transfer; the current recipes do not enter these fields automatically. Video input is rejected before launch until an inspection workflow exists.

Completed Translate sections stay collapsed and do not repeat the platform messages. Review the loaded drafts in Platform text or Preview; Save platform text is at the top of the editor. New translations include a supplied relevant project/resource link by default for Discord, WhatsApp Channel, Telegram Channel, Medium and Tumblr, using the GitHub URL when relevant. Missing URLs are never invented, and this preference makes no claim about platform ranking policies. Previously saved drafts are unchanged.

**Platform text → Load JSON** accepts a UTF-8 schema 2.0 content pack as a file or pasted JSON, including a complete tagged capture block. It requires `source.text`, `destinations`, and matching `posts` keys, with each platform's `message`, native `title`, `tags` and optional editorial metadata. A pipeline `run_id` does not need to exist locally. If supplied, `source_revision` must match the current post; portable packs without that field still require exact source text. Loading replaces the pending pack, not the saved selection. Review and save before Sow. Wrong-source, stale, unknown-platform, duplicate-key and over-limit files are rejected before any mutation. Imported status cannot confirm publication or approve a platform test; unavailable preparation remains held.

**Download saved JSON** exports the effective saved versions in the same content-pack format. Manual copy does not have to pass AI editorial rules such as every message being distinct or Twitter matching the source; structural validation, length limits, platform availability and the normal approval gate still apply. The original source, prior captured JSON and receipts are never rewritten by editing copy.

## Implementation and repair

- UI and orchestration: `translations.py`, `translation_panel.html`, `post.js`, the existing single-run worker and its controls.
- Browser configuration: `plugins/chatgpt_translation.yaml`. This is `kind: translation`, excluded from social plugins. Change composer labels, copied-HTML selectors and timing here when ChatGPT changes layout.
- Image upload completion uses a read-only Windows accessibility snapshot: the expected number of attachment removal controls, no progress bar or upload error, and an enabled Send control must be present on two consecutive checks. It does not compare pixels, crop, filename or image identity; the run's saved source file is trusted. It never clicks Send during these checks. Upload controls and the 120-second timeout are defined in YAML. New-chat startup checks the exact root URL and locates the empty composer placeholder with local screenshot/OCR. It does not copy the empty page, click welcome text, or traverse the Thinking effort control. Placeholder alternatives and screen regions live in YAML. Only an absent label permits trying the next alternative; ambiguous matches and focus/input guards stop immediately. Both full prompt copy-back checks must pass before the single ChatGPT submission. Current and older assistant markup are supported for response capture, with nested matches deduplicated so the prompt cannot be mistaken for the result.
- `plugins/chatgpt_translation.yaml` now contains the full sequence, with named primitive actions, typed `{ref: variable}` inputs, `save_as` outputs, explicit `for_each` loops and bounded read-only `poll` blocks. There are no `translation_query` or `translation_capture` action modules.
- `roboclick/workflow.py` only sequences the recipe and supplies reusable local-data operations. Each leaf dispatches through the existing pinned oomlout framework/action discovery, using existing desktop primitives and generic additions in `roboclick/workflow_actions/`. Those additions and the sequencer are mirrored into `C:/gh/oomlout_roboclick/`. See [ROBOCLICK_WORKFLOWS.md](ROBOCLICK_WORKFLOWS.md).
- `translation_browser.py` supplies the saved prompt/images/tags, reserves the guarded desktop, applies the existing countdown, and enforces the single authorized ChatGPT submission. Its policy does not perform UI actions or contain UI selectors. It rejects a submission unless the actual pasted prompt, completed uploads, URL recheck and two fresh text comparisons succeeded. Final content-pack validation and import remain in the Allotment adapter.
- The explicit user-requested AI query is the only prompt-submission operation: verify the fresh root URL, an empty composer placeholder, completed image uploads and all prompt wording, recheck the exact root URL and composer, then the configured AI prompt shortcut once (currently Enter). Require a new conversation URL before waiting for output. This exception does not add a submit action to any social recipe. An ambiguous or missing check stops before submission.
- After leaving the composer, ordinary keyboard page copy captures Windows CF_HTML. Only assistant-role content is eligible. Opening and closing tags include a unique run token. Accept one stable complete JSON response with the matching run/source/destinations; never accept the prompt echo, stale clipboard, partial output, duplicate JSON keys or whole-page fallback. Unicode is preserved. The exact original tweet is validated independently of clipboard paragraph spacing.
- Capture waits up to the configured timeout. Errors leave the chat open and never automatically resubmit the prompt. Stop or a focus/input guard also leaves the tab intact. Review the evidence before starting another generation.
- Translate shows the current top-level step and image/prompt-chunk position. Waits show their reason and a live countdown; response polling also shows the next check, check number and overall timeout. Progress is persisted with the run and restored on reload. A user-paused initial countdown explains that Resume is required. Completed or stopped runs hide obsolete timers.
- Runs, source image copies, guide snapshots, prompts, captured pages, screenshots and JSON live under `.local/job-runs/<namespace>/<user>/<run>/`. Selection and confirmed context live under `.local/translations/<namespace>/<user>/<post>/`. These files are private and ignored. Sow snapshots the selected platform message and translation metadata alongside the existing destination payload.
- Editable versions use `platform-text.yaml` in that private post directory. `pending-platform-text.yaml` holds a captured/imported pack awaiting review. `platform_text.py` handles loading, validation and edits; it does not drive the browser. Saving or choosing the original clears the pending pack. Existing Sow snapshots stay immutable when copy is changed later.
- Source revision and guide checksum are stored with each run. A guide edit affects the next run; it does not silently replace reviewed versions or invalidate unrelated social approvals. No generated content or test is automatically approved.

## Manual web guide

The post page’s Guide link opens `/g/<namespace>/<user>/translation-guide/?post_id=<post>` in a new tab. This is a read-only HTML checklist generated from the current YAML on explicit request. It includes the post’s full copyable prompt with fresh capture tags, original-image links, input definitions, ordered primitive steps, loop/poll timing and manual result-import instructions. It creates no run, approval or saved translation. A general guide is available without post_id; the existing `translation-guide.md` URL still downloads the writing instructions.

`C:/gh/oomlout_roboclick/roboclick_guide.py` provides reusable `render_yaml_guide` and `write_yaml_guide` functions plus an explicit CLI requiring `--output`. The standalone renderer is mirrored as `allotment/workflow_guide.py`, outside the signed social runtime. Keep these files identical when updating the renderer. Normal startup and workflow execution never generate guides. Unknown actions retain exact parameters and are labelled as needing a manual procedure; an optional `manual_instructions` argument supplies prose by command without changing executable YAML.

All platform length limits are now handled before browser preparation: translation validation, JSON import, manual saves and Sow snapshots truncate to each recipe’s configured max_chars without an ellipsis. Medium counts title, two newlines and body together; an overlong title is shortened while retaining a body field. The full source post and automatic website/summary snapshots are preserved. At-limit translated results remain reloadable even if truncation removed a disclosure or distinctive ending. Existing schema, source, hold and preparation-approval gates still apply. This normalization lives outside the signed browser runtime, leaving platform approval fingerprints unchanged.
